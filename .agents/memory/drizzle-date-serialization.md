---
name: Drizzle date serialization
description: Drizzle ORM returns JS Date objects; Zod schemas generated by Orval expect ISO strings. Fix by running serialize() before any Zod .parse() call.
---

## Rule
Always call `serialize(data)` before passing database results to Zod's `.parse()`.

**Why:** Drizzle/pg-core timestamps come back as JavaScript `Date` objects. Orval-generated Zod schemas use `z.string()` for all date/datetime fields (based on OpenAPI `format: date-time`). Passing a `Date` to `z.string()` throws a ZodError "Expected string, received date".

**How to apply:** Import `serialize` from `../lib/serialize` in every route file. The helper does `JSON.parse(JSON.stringify(data))`, which calls `Date.toJSON()` and produces ISO strings. Use it for response data only — Zod input validation for request bodies is fine as-is since clients send strings.

```ts
import { serialize } from "../lib/serialize";
// ...
res.json(serialize(rows));       // correct
res.json(rows);                  // wrong — Date fields cause 500s
```
